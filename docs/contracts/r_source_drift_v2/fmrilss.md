# R-source drift v2: fmrilss 0.2.0 (dev; NEWS "development version") (`f851fb0`..`188d0dd`)

Part of [`r_source_drift_inventory_v2.md`](../r_source_drift_inventory_v2.md). The classes, method and wave plan are defined there. `repro/` scripts run against fmrimod HEAD `4f14a19` with `.venv/bin/python`.

Range: 36 non-merge commits (plus 5 merges), 32 R/src files changed. Refactor-only work: most of the line count is GLMsingle planning/benchmark commits (`40cb4cf`..`ed013ab`, `b654a06`), vignette editorial passes and the albersdown 2.1 theme (`b7e7ff1`, `dfc81c9`, `d2fac1a`, `5598961`), vignette recalibration for fmrihrf's corrected SPMG HRFs (`1ff0867`, `e91113e`; that drift belongs to fmrihrf, not fmrilss), CI/metadata/doc-check repairs (`526f57d`, `6831fc8`), the Python benchmark harness (`c96b0c1`), and Rcpp plumbing (`RcppExports`, `all_finite_cpp`/`.all_finite`, `voxel_acf_cpp`, `.blas_is_threaded` OpenMP-vs-BLAS switching). Three performance rewrites give the same numbers. (1) The weight-matrix LSS kernel (`61b65b4`; `R/lss_kernel.R`) computes `W'Y` and drops the dead helpers `.project_R_optimized` and `.lss_beta_vec_optimized`. (2) The noise plan is fitted from an n-column factor of the residual Gram matrix (`6782b5b`; `R/lss_prewhiten_kernel.R:112-161`; R's test `compressed noise fit reproduces the full-residual AR plan` checks this to 1e-10). (3) Noise residuals use BLAS-3 projections (`.noise_residuals`). The one kernel change that alters behavior is in a done row (LSS-11). `8d7fbd2` (`stats::prcomp` qualification) and the DESCRIPTION ORCID/Copyright edits are housekeeping.

## Open questions
- **Pre-existing, not upstream drift, but verified wrong.** With `prewhiten` active, `estimate_single_trial(..., include_intercept=True)` adds an **unwhitened** column of ones after whitening (`fmrimod/single/__init__.py:143-154` then `fmrimod/single/lss.py:362-367`). R whitens `Z` (intercept by default) with the same plan. On a mean-100, 2-run AR(1) fixture, betas differ by up to 0.999 (true betas ≈1) from `baseline_regressors=ones` (`repro/fmrilss_intercept_whiten.py`). Deserves its own bead; the fix is to route `include_intercept` into `baseline_regressors` before `prewhiten_matrices`.
- **Pre-existing, code-read only.** R `lss_design()` always adds run intercepts from block IDs or the frame (`R/lss_design.R:332-343`). `estimate_single_trial_from_dataset` adds only `prepared.fixed` (non-trialwise event terms) plus an optional *global* intercept (`fmrimod/single/__init__.py:425,443`). Multi-run datasets therefore get no run intercepts unless the user passes them as confounds. Confirm whether that is a deliberate redesign; if not, file it with LSS-03.
- **LSS-02 scope.** The positive-peak/orientation contract predates the v1 pin, so v1 missed it. Port it in full (recommended, given the sign flip), or keep unit-L2 as a documented fmrimod choice with a CAVEATS row? Porting needs an evaluable basis object; today `estimate_voxel_hrf(basis=...)` treats `basis` as metadata only.
- **LSS-05 k-means parity.** R uses `stats::kmeans` (Hartigan–Wong, quantile-initialized centers; Lloyd fallback). SciPy's `kmeans2` is Lloyd. Is a CAVEATS row acceptable, or should `voxel_bins=V` be the only exactly gated configuration?
- **LSS-09 GLMsingle.** Upstream's reference implementation is Python. Should fmrimod port R's faster re-implementation (claimed 18–24× over Python GLMsingle), wrap the Python package as an optional backend, or scope it out? Needs a steward decision.
- **LSS-03 classification.** It is labelled wrong-result because the fmrimod dataset path silently differs from R on valid multi-run input. Only the SBHM half is new since the pin; the `lss_design` half was already in R at `f851fb0`.
