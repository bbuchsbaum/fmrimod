# R-source drift v2: fmridataset 0.11.0.9000 (`a8bf021`..`58c9f4c`)

Part of [`r_source_drift_inventory_v2.md`](../r_source_drift_inventory_v2.md). The classes, method and wave plan are defined there. `repro/` scripts run against fmrimod HEAD `4f14a19` with `.venv/bin/python`.

Range: 140 non-merge commits, 78 R files changed (43 deleted, 32 added, 3 modified; the package has no `src/`). Upstream rebuilt the package in this range. The pre-frame surface that fmrimod ports was fixed in place until `3ae565e` (2026-08-28), then deleted in `f305b44` (2026-09-06) and replaced by the `fmri_frame` architecture. **No R code at HEAD corresponds to `fmrimod.dataset`.** Most correctness rows below therefore compare fmrimod against either the last legacy fixes (`7dad6c0`, `631cf0d`, `e19e27d`, `e998bd4`) or the semantic contracts that the frame rewrite made explicit (run identity, per-run timing, selection law, spatial identity). Refactor-only work, no rows: the behaviour-preserving cyclomatic-complexity split (`0d3a0a5`, which says "test suite byte-identical"); lint, theme and styler passes (`b83be4d`, `ea18bcc`, five "Style code" commits); roxygen/Rd regeneration (`912a45f`, `7005ddc`, `0a90e4c`, `d44c684`, `d766c44`); the testthat-edition-3 migration and CI/test-honesty work (`47581e4`, `17d6efa` test half, `2842791`, `9c46f90`, `f3ad161`, `0938f77`, `8bd865c`, `a488023`, `7f9cf93`, `b16b1b2`, `a54b79a`, `df527c5`, `3ae565e`); planning/bead "Close … ticket" commits; dependency plumbing (Bioconductor drop `9421a4c`, delarr pins `72994b9`/`49efb4f`, fmrihrf moved to Suggests); the DelayedArray retirement (`2964c1f`); CRAN housekeeping (`fbb25d4`, `3157f0c`, `c3283e8`); removal of dead helpers and aliases (`9a91e5c`, `7151f31`); and the version bump (`c813d7a`).

## Baseline

fmridataset was never audited, so the baseline was inferred from what fmrimod ports:

- **What fmrimod ports.** `fmrimod.dataset` (`__init__.py:213-275`) and the thin facade `fmridataset/__init__.py:1-36` mirror the **pre-frame** R surface:
  - `FmriDataset`, matrix, NIfTI and latent backends, and the backend registry;
  - `data_chunks`/`exec_strategy`, `fmri_series` and the selectors;
  - `study_dataset`/`fmri_group`;
  - BIDS-HDF5 in both parcellated and latent modes. This includes the shared-template loadings fallback and the per-scan `offset` from `362f76f`/`c8b183c` (`fmrimod/dataset/bids_h5.py:426-478`, `:479-507`).

  `docs/tutorials/datasets.qmd` documents the same surface. None of the frame API exists.
- **Provenance.** The Python port began in the R repo and was split out at `57dfbc0` (2026-02-17, "Remove Python port (moved to separate repo)"). That donor, `fmridataset-py`, was then folded in under `docs/contracts/fmridataset_consolidation_plan_v1.md` (dated 2026-05-12; it describes the donor as owning BIDS-HDF5 parcellated and latent read/write). fmrimod's own history is shallow from 2026-05-16, so the donor commits are not visible.
- **Chosen baseline: `a8bf021`** (2026-03-29), the last change to legacy R code before the port. The R code is byte-identical from there through `ad1ae84` (2026-05-05). NEWS heading "fmridataset 0.9.0 (Development)"; DESCRIPTION 0.8.9.
  - Evidence it is not earlier: the BIDS-HDF5 latent mode, shared templates and offsets (all 2026-03-29) are present.
  - Evidence it is not later: the legacy fixes `7dad6c0` (2026-05-05, DS-11), `631cf0d` (#81, DS-10), `e19e27d` (#82) and `e998bd4` (DS-02) are absent or only re-derived. #82's capability exists through fmrimod's own neuroim redesign, not through a port of the R fix.
  - `3ae565e` (2026-08-28) is the last revision with any legacy surface. Everything after it is frame architecture.

- **DS-01**

Hand-write an archive (the file already does this with `_write_str_array`) holding one subject with scans `ses-01…run-1` and `ses-02…run-1`, one event each at different onsets. Build the event model the way `fmri_lm(spec, dataset)` does with `block=None`. Assert that the second event's regressor is non-zero only in rows 20-39. ## Open questions

- **Event-model block mapping (cross-package; route to the fmridesign audit).** `fmrimod/design/event_model.py:2474-2481` renumbers block labels by first appearance among *event rows*. Events that exist only in run 2 therefore land in run 1 (`_parse_block_ids("run", {"run": [2]}) -> [1]`, verified inline). This affects every dataset whose first run has no events, and it blocks a clean DS-01 fix.
- **`compress_bids_study` silently discards `encoding=` and `template=`** (`fmrimod/dataset/bids_h5_write.py:427`). R has had a shared-template writer since `362f76f`/`4520bf6`, which predates the baseline, so this is a baseline gap, not drift. Should it raise `NotImplementedError` until it is ported?
- **Baseline divergences seen in passing, not in range:**
  - `latent_dataset(tr=1.0)` has a default (`fmrimod/dataset/latent.py:180`), while R requires `TR`.
  - Mask binarization disagrees across paths: `NiftiBackend` uses `> 0` (`nifti_backend.py:97`), `NeuroVecAdapter` uses `astype(bool)`, which maps NaN to True (`neuroim_adapter.py:257-258`), and R uses `as.logical` (nonzero, NA stays NA).
  - `SamplingFrame.from_dict` defaults `start_time` to 0.0, not TR/2 (`fmrimod/sampling.py:347`; fmrihrf lineage).
- **Unverified:** the BIDS-directory path in `compress_bids_study` never filters on `space=` (stored as metadata only, as in legacy R). fMRIPrep derivatives with several spaces would produce colliding scan names, whereas R HEAD's `read_bids_bold` fails explicitly on spatial ambiguity. pybids is not installed in `.venv`, so this was not run.
- **DS-02 shape:** should the study lowering emit `VoxelSpace` (S2, a seam change) or keep `SampleLabelSpace` and only refuse or route? The routing fix alone closes the wrong result.
- **Baseline confidence:** the `fmridataset-py` donor history is not visible, so `a8bf021` is inferred from feature presence. The rows do not depend on the exact baseline, because none of DS-01 to DS-14 has a fmrimod counterpart of an R fix made between `a8bf021` and `7dad6c0`.
