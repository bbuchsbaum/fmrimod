# R-source drift v2: fmrireg 0.3.0.9000: group, meta, output, plugins (`063c8ef`..`0321e77`)

Part of [`r_source_drift_inventory_v2.md`](../r_source_drift_inventory_v2.md). The classes, method and wave plan are defined there. `repro/` scripts run against fmrimod HEAD `4f14a19` with `.venv/bin/python`.

Range: 166 non-merge commits and 92 R/src files changed across the whole package. This half covers 39 of those files (group/meta/t-test/spatial-FDR/BIDS export/plotting/plugin API/frame helpers/infra, listed in the brief) and the commits, NEWS entries and tests that touch them. The main sources are the "review 2026-10" streams A, B and E (`data-raw/review-2026-10-plan.md`, `tests/testthat/test-review-{A,B,E}-*.R`), plus the simplification phases P1-P3 (`test-simplify-2026-10-*.R`). In P1-P3 the R group layer delegates to fmrigds.

Refactor-only work (no rows): The "simplification 2026-10" phases 1-2 removed about 3,150 lines of unreachable R and C++ code (`832fa39`, `e9e724a`, `d16d6d6`, `4722e2d`, `aaa109f`). `c7cb723` folded the meta C++ code into one kernel, `meta_fit_cov_cpp()`, with identical results. `ba58f1a` drives `write_results()` from one output plan and one writer, with unchanged files and JSON. `ff1bf76` and `bd5b5d6` added one packager for externally fitted results and simplified engine plumbing. `27d1543` and `1862702` moved R-level parallelism to future.apply, dropped RcppParallel and kept one OpenMP thread helper. `2b16f1f` moved tidyr, plotly and bslib to Suggests. The frame-API migration covered `fmri_frame_helpers.R`, `spatial_mask_helpers.R`, `dataset_spec()` constructor names and `fmri_job.R` (`f5f6dd9`, `fcc9888`, `26d01e4`). The rest is roxygen and `$`-method registration (`6147595`), codemeta, CI pins and README/NEWS version syncs.

The large deletions are moves and consolidation; no feature was dropped:
- `src/spatial_fdr.cpp` (-317) was removed after it was ported as `fmrigds::spatial_fdr_sabha()` (`3ea2a2b`), with identical results. The A1/A2 and finite-`m_g` fixes landed in fmrireg first (`af12983`, `c8c6021`) and were carried into fmrigds.
- `R/fmri_ttest_gds.R` (-341) became one input path through fmrigds `ols:voxelwise` / `ttest:welch` (`3ed5e8d`). The deleted gds method had bugs: it fitted only the first contrast, gave the Welch SE as NA, and returned pinv estimates for rank-deficient designs.
- `R/fmri_meta_gds.R` (-700) now reduces with one registered `"fmrireg:meta_reg"` reducer plus `fmrigds::coef_contrast()` (`cfb4389`). This also fixed a silent "first contrast only" bug.
- `src/inst_correlation.cpp` was fixed (C9, `7c2a985`) and then deleted as unreachable (`832fa39`).
- `R/correlation_map_methods.R` moved to fmridesign (`616e6d5`).

Where R removed something because it was wrong and fmrimod still has it, there is a row: absolute-variance "equal"/"custom" weights (REG-B-01), row-only kernel normalisation (REG-B-06), absolute SE thresholds (REG-B-07), and a `reml` label without its own estimator (REG-B-08).
